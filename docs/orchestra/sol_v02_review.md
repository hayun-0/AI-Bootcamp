확인된 정상 경로도 있습니다. 일반 inspect·resolve 중복은 조건부 상태 UPDATE가 막고, cancel은 전액 환불합니다. release는 보류금을 유지하며 배정·운임을 지웁니다. withdraw와 order는 같은 판매 행의 상태 조건으로 경쟁합니다. 일반 회사의 `/me` 목록과 `/bags/{id}`는 소유자를 검사하고, 판매 상세는 계약에 명시된 공개 필드만 반환합니다. 운영자 생성은 환경변수 토큰과 `compare_digest`를 사용하며, 첫 LLM 예외 이후 해당 run의 추가 호출을 차단하는 회로도 적용돼 있습니다.

검증 결과는 **하네스 비HTTP 테스트 55개 통과**입니다. 전체 pytest는 첫 인수 테스트의 `TestClient.__enter__`에서 대기해 제한 시간 후 종료했습니다. 따라서 전체 HTTP·PostgreSQL 통과는 확인하지 못했습니다.

우선 수정 5개는 다음과 같습니다.

1. **정산 재원 정책 확정:** 정상 +5%·regrade 초과분을 묵시적으로 삭감하지 않도록 처리하고, treat의 별도 청구·수취를 명시.
2. **금액 정확성 확보:** 최초 입력·합산부터 Decimal을 유지하고 PostgreSQL 금액 열을 BigInteger 등으로 변경.
3. **재배차 경합 차단:** 상태 변경 조건에 배정자와 배차 버전을 포함.
4. **LLM 입력·출력 경계 보완:** 사용자 문자열을 주장 생성 단계에서 가리고, 등급·가격 관계의 부정·활용형 회귀 사례 추가.
5. **실행 기록 접근 격리:** run에 소유자·관련 거래를 저장하고 DB·메모리 조회 모두 권한 확인.
