## 3. 남은 위험 분류 (구미 시범 운영 전 vs 외부 공개 전)

### 가. 구미 시범 운영 전에 꼭 할 것 (운영·환경 설정)
1. **운영 환경변수 및 시드 고정**: 배포 서버(Azure PostgreSQL 연동 환경)에 강력한 `OPERATOR_BOOTSTRAP_TOKEN`을 설정하고, 시범 참여 업체(공장·재활용·운반) 및 운영자 계정을 시드/사전 등록으로 발급할 것.
2. **프론트엔드 텍스트 이스케이프(XSS 방어)**: `GET /v1/bags/{id}`, `GET /v1/orders/{id}` 등 거래 당사자 전용 상세 응답에는 업체명·메모·품목 원문이 포함되므로, 프론트엔드 렌더링 시 HTML 이스케이프(React 기본 텍스트 바인딩 등)를 강제하고 `dangerouslySetInnerHTML` 사용을 금지할 것.
3. **Ollama 모델 워밍업 및 타임아웃 운영 점검**: 첫 Ollama 호출 시 모델 로딩 지연(최초 1회 15초 타임아웃 후 템플릿 전환 가능)을 줄이기 위해 서버 기동 후 1회 워밍업 호출(`keep_alive` 설정)을 넣어둘 것.
4. **CI 파이프라인 PostgreSQL 테스트 상시화**: SQLite에서 건너뛰는 동시성 테스트 10건(`FOR UPDATE` 등)이 누락되지 않도록 CI에서 PostgreSQL 테스트를 필수로 실행할 것.

### 나. 외부 공개(실제 배포) 전에 할 것 (보안·인프라·법률)
1. **실제 인증·세션/JWT 도입 (`X-Company-Id` 폐기)**: 현재 P0 한정으로 허용된 `X-Company-Id` 헤더 숫자 변경만으로도 타사·운영자 사칭(04#0)이 가능하므로, 외부 공개 전 반드시 로그인 인증(JWT/세션)으로 교체할 것.
2. **네트워크 보호 (Rate Limiting · 요청 본문 크기 제한 · CORS)**: 리버스 프록시 또는 미들웨어에서 IP/계정당 요청 빈도 제한(특히 LLM 호출 경로), 요청 바디 크기 상한, 허용 프론트엔드 도메인 CORS 제한을 설정할 것.
3. **반송(`return`)·처리 전환(`treat`) 법률 자문 및 후속 배차(P1)**: 현재 `legal_note: "법률 자문 확인 필요"` 문구로 안내 중인 불합격 폐기물 반송·처리 전환의 폐기물관리법상 적법성 자문을 완료하고, 반송용 재배차 플로우 및 실제 PG 정산/청구 연동을 구현할 것.
4. **배차 후 운반업체 체크리스트 열람 권한(선택)**: 주문 시 생성된 `deal_check` 실행 기록(`agent_runs.company_ids`)에 배차 수락(`accept`) 시점의 운반업체 ID도 추가할지 필요에 따라 반영할 것.
