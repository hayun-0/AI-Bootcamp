## 2. 비밀키 점검
- 확인: 저장소·로그에서 `sk-ant`, `ANTHROPIC_API_KEY=` 값, 비밀번호 문자열 없음. 코드는 환경변수만 사용(`llm/claude.py:23`), `/v1/health`·`/v1/harness`·에러 응답에 키 없음, 서버 로그(qa_4.log)에서도 키/비밀번호 검색 결과 없음.
- 확인: 다만 DB 오류가 나면 서버 로그에 SQL 문+파라미터가 그대로 기록됨(#6). `DATABASE_URL`에 비밀번호가 들어 있으면 SQLAlchemy 연결 오류 때 로그에 노출될 수 있음(추정).
- 추정: `AgentResult.error`에 예외 메시지 앞 300자가 담겨 `/v1/agent-runs`로 공개됨(`harness/runner.py:57`). Ollama 연결 실패 시 내부 URL, Claude 오류 시 오류 본문이 포함될 수 있음. LLM off에서는 재현 불가, LLM 켠 상태 테스트 필요.

## 3. 잘 막힌 것 (확인)
- 마대·판매글 IDOR: 남의 마대로 등급/판매글 생성 -> 403.
- 주문·인계서 열람: 당사자 아닌 공장/운반업체/운영자 -> 403 (`GET /v1/orders/{id}`, `/handover`).
- 남의 인계서 칸 작성 -> 403, 수거를 재활용업체가 시도 -> 403.
- 역할 혼동: 공장이 주문, 재활용업체가 verify, 미배정 운반업체 pickup -> 403. 일반 사용자 verify 자체 -> 403.
- Mass assignment: `verified`, `id`, `status`, `grade`, `factory_id`, `total_kg`, `goods_krw` 추가 필드는 모두 무시됨(응답과 DB로 확인: 가입 `verified:true` 시도는 false 유지, 판매글 `status:"sold"`도 무시).
- 주문·수락 경쟁: 재활용업체 8개 동시 주문 → 201 1개, 409 7개 / 운반업체 8개 동시 수락 → 200 1개, 이력 2건(`create_order`/`accept_call` 조건부 UPDATE 효과).
- 상태 건너뛰기: 수거 전 arrive, 수거 전 inspect, 중복 수락 -> 모두 403/409.
- SQL 인젝션: `waste_code` 쿼리의 `' OR '1'='1`, `; DROP TABLE` -> 빈 배열(파라미터 바인딩). 인계서 문자열에 SQL 조각 저장은 문자열로만 취급.
- 점수 범위(1~5), NaN kg, 깊게 중첩된 JSON(10만 단계) -> 400.
- 자기 평가·제3자 평가 -> 403, 중복 평가 -> 409.
- 에러 본문에 스택트레이스/내부 경로 없음("Internal Server Error"만).

## 4. 좋았던 점 3개
1. 거래 경쟁 상태 중 가장 위험한 두 곳(주문 선점, 배차 수락)을 조건부 UPDATE로 정확히 막았고 동시 8요청에서 1건만 성공.
2. 객체 수준 권한(당사자 확인, 칸 주인 확인)이 일관되고 mass assignment가 없음(Pydantic이 추가 필드를 버림).
3. 에러 응답이 안전("Internal Server Error"만), 쿼리가 전부 파라미터 바인딩이며, 하네스 게이트(개인정보 정규식)와 LLM 키 환경변수 사용으로 비밀 처리가 깔끔함.

## 5. 가장 먼저 고칠 것 3개
1. **#1 운영자 가입 차단 + #17**: `POST /v1/companies`에서 `operator` 금지(운영자는 DB 시드/별도 경로), 재활용·운반은 승인 전 `verified=false` 유지. 그리고 인증 도입(#0).
2. **#2, #3 동시성**: 판매글 생성은 `UPDATE bags SET listing_id=... WHERE id IN (...) AND listing_id IS NULL`의 rowcount 검사 또는 `SELECT ... FOR UPDATE`, 주문 상태 전이(`pickup/arrive/inspect`)도 `UPDATE ... WHERE status=이전상태` 조건부 갱신으로 통일.
3. **#4, #5, #6, #10, #11 입력 검증**: 모든 float `allow_inf_nan=False`, 정수 `le=`, 문자열/배열 `max_length`/`max_items`, NUL 문자 거부, 운반비·무게 허용 오차(계약서에 먼저 추가), 전역 레이트 리밋/요청 크기 제한. `/v1/harness`는 카드·내부 URL·가정값을 빼거나 운영자 전용으로.
