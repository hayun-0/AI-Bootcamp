실제 HTTP로 공장·재활용업체·운반업체 앱 화면 세 개를 만든다고 생각하고 필요한 호출을 해 본다:
- 화면마다 필요한 목록·상세 조회가 다 있는가(내 마대 목록, 내 판매, 내 주문, 받은 콜 이력, 알림 등). 없는 것 목록.
- 응답 모양이 일관적인가(필드 이름, id 타입, 날짜 형식, 에러 응답 형식, 한글/영어 섞임), 페이지 나누기·정렬, OpenAPI 문서(/docs, /openapi.json) 품질.
- 상태 값 이름과 화면 표시 문구 대응, 실시간 갱신(콜 알림, 주문 상태)을 앱이 어떻게 알 수 있는지.
- AI 결과(RunResult)를 화면에 그리기 좋은 모양인지(너무 큰지, 사람용 문장과 기계용 데이터가 나뉘었는지).
보고 형식은 브리프의 표, 한국어. 마지막에 프론트 붙이기 전에 꼭 필요한 API 추가 목록(우선순위).
