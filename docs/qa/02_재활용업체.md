## 좋았던 점 3
1. 동시 요청에서 주문 1건만 성립, 운반 수락도 1곳만. 조건부 UPDATE 가 잘 작동(409 메시지 명확).
2. 역할·허가·검증 순서 403/404/409 가 계약대로 일관되고, 입력 오류는 422 대신 한글 400 으로 읽기 쉽다.
3. 주문에 상태 이력(history)과 빈 칸 `null` 로 보이는 인계서 구조가 명확해 흐름을 따라가기 쉽다. 본인 칸만 쓰기 규칙이 잘 지켜진다.

## 가장 먼저 고칠 것 3
1. 불합격(disputed) 출구와 주문 취소/수락 기한(자동 만료) - 구매자 돈이 영구히 묶인다 (#2, #3).
2. 정산을 검사 무게 기준으로(또는 허용오차 초과 시 자동 disputed), 수거 무게 이상 징후 경고 - 모자란 물건에 전액 지급 방지 (#1, #7).
3. 운임을 구매자 동의 단계로 만들고(상한·견적·승인), 숫자 범위 검증으로 500 제거 (#4, #5, #6). 이어서 목록에 순도·재질구성·공장명·위치 노출 (#9).
